## 一、真实 DSH 端到端验证（待授权）

**配对二维码（需求 #11 桥接模式说明，阶段 A 问题 A-21 补文档）**：任意二维码工具（建议本机离线生成）把 `http://<电脑IP>:3090/<设备令牌>` 编码为二维码，手机端连接页输入框扫码/粘贴即可。安全提示：该二维码内容=设备凭据，生成后视为敏感物——不要存相册/聊天记录；怀疑泄露时在 PC 上 `node bridge.js devices revoke <id>` 撤销后 `devices add` 重新发放。

**前置条件（全部就绪）**：桥接 27/27 测试、手机端 411+412 项单测（阶段三回归数以汇总为准）、协议兼容矩阵（0.1.7-rc.2 逐字取证）、mock 全链路通过。

**测试步骤（授权后约 15 分钟）**：
1. 你手动执行 `dsh web`（保持默认 127.0.0.1:3080），从启动输出复制本次 launch token。
2. 启动桥接（托盘或命令行）；`node bridge.js devices add 手机` 获取设备令牌。
3. 手机端主机地址填 `http://<电脑IP>:3090/<设备令牌>`，连接。
4. 在 DSH 启动 URL 页面（电脑浏览器）正常使用的同时，手机端：新建会话→发送一条无副作用消息（如"回复 pong 两个字母"）→ 观察真实流式输出 → 对 DSH 弹出的真实审批（若触发）执行批准/拒绝 → 观察事件时间线。
5. 核对项：事件顺序与电脑端一致；审批结果真实约束 DSH 执行；断开手机网络后状态如实显示、重连不重发。
6. 副作用与回滚：新增一个测试会话（可在 DSH 端删除）；无其他副作用；launch token 由你粘贴、不落任何报告。

**需要的权限**：仅"由你启动 dsh web 并粘贴 token"这一步；无系统/网络/DSH 配置变更。
