## 二、明文 HTTP 独立风险分析（不做网络可达性=加密的混同）

- 事实：桥接与手机之间为明文 HTTP/WS（局域网模式），令牌经 URL 路径传递。可达性层的加密（Tailscale/WireGuard）**不改变**这一点——它保护的是网络段，不是应用层端到端。
- 威胁链（继承 DSH-Remote 评审框架）：局域网嗅探者若获取"桥接令牌 + DSH launch token"其中之一的效果——桥接令牌单独无用（还需 DSH cookie/launch token 才能过 DSH 的 401）；DSH cookie 一旦被窃即等同完整 Host API 权限（官方警告：cookie=RCE 级）。
- 现有缓解与边界：回环默认 + 双层凭据 fail-closed + 日志脱敏 + 无公网组件；**未做**应用层 TLS/E2EE（明确不在本次范围，改进方向已记录：桥接可选 `--tls-cert/key` 透传 DSH 原生 HTTPS，或沿用上游 relay 插件通道）。
- 结论：明文风险如实保留在交付文档显著位置；私有网络降低暴露面但**不等同于**应用层加密。
