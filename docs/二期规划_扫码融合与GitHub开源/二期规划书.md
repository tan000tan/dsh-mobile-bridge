# 二期规划书：扫码配对融合 + GitHub 开源

生成：2026-10-25。性质：**规划文档（未执行任何改造/推送）**。依据：网上现成方案检索（来源附文末）+ 本机项目实查（目录结构、敏感文件清点均于 2026-10-25 实测）。

---

## 一、目标与结论

**目标**：给 DSH手机控制台 App 增加"扫码即用"模式——扫 dsh-remote-web-ui 插件二维码 → App 内置 WebView 直接进入已配对的官方界面，摆脱外部浏览器/微信；同时把本项目整理后上传 GitHub。

**结论**：方案可行（一期评估成立），总工作量约 1.5~2 个工作日（含回归与构建，构建链复用现有）。全程零改动 DSH、零改动插件、零改动桥接、PC 侧只新增文件不修改旧文件；手机侧仅安装新 APK（新增相机权限一项）。

**总原则**（贯穿所有阶段）：
1. 不动现有可用链路：桥接模式（设备令牌+3090）保留原样，扫码模式是并列新增入口。
2. 改码前备份，每阶段可独立回滚；APK 哈希入档。
3. 诚实标注：模拟测试 ≠ 真实验收；真机扫码全链路必须实测后才算完成。
4. PC 影响最小：所有新文件集中在二期目录与 App 源码新增文件；GitHub 导出用**策展副本**（复制+脱敏），绝不动原件。

## 二、网上现成方案盘点（本轮检索结论）

| 需求 | 现成方案 | 结论 |
|---|---|---|
| 扫码库 | **zxing-android-embedded**（journeyapps，战斗检验）vs ML Kit+CameraX（现代、Google 维护，如 quickie 库） | **选 zxing-android-embedded**：与现有 Kotlin/Compose 工程集成最简、无 Google Play 服务依赖、离线可用；ML Kit 作备选（若要求更强弱光识别再换） |
| WebView 会话保持 | CookieManager（`setAcceptCookie(true)` + `flush()`）+ ServiceWorkerController（显式启用 SW） | 直接套用官方 API；注意 Cookie 约 2 周闲置会被系统驱逐（见问题表 P2） |
| 域名稳定性 | trycloudflare 快速地址**每次重启变化**，Cookie/SW 都是 origin 级绑定 | 必须锚定插件默认开启的固定域名中继（`*.dsh-market.com`）或命名隧道；二维码里的快速地址仅作首次入口 |
| WebView 安全 | shouldOverrideUrlLoading 白名单拦截 | 自实现（P1 问题），无现成轮子但模式标准 |

## 三、总体架构

```
手机 App
├── 现有：桥接模式（主机设置页 + 设备令牌 → 172.x.x.x:3090 桥接 → dsh web 0.1.7）
│   └── 完全不动，继续可用
└── 新增：扫码模式
    ├── 扫码 Activity（zxing-android-embedded，相机权限）
    │     └── 仅接受白名单域名 URL（*.dsh-market.com / *.trycloudflare.com / 局域网 IP 白名单可选）
    ├── WebView 壳 Activity
    │     ├── CookieManager 持久化 + flush()
    │     ├── ServiceWorkerController 显式启用
    │     ├── 返回键=历史后退，双击退出
    │     └── 禁 http 明文（cleartext=false，只走 https 隧道/中继）
    └── 配对状态页：显示当前锚定域名、设备名、一键"解除配对"（清 Cookie+SW）
```

插件侧、PC 侧、DSH 侧：**零改动**。扫码模式只是"一台自带浏览器的配对设备"。

## 五、可能出现的问题与对策（P 表）

| # | 问题 | 对策 |
|---|---|---|
| P1 | 恶意二维码把 WebView 导向钓鱼页 | 白名单硬闸（S5）；默认拒绝一切非清单域名 |
| P2 | WebView Cookie 约 2 周闲置被系统驱逐 → "莫名要重扫" | 锚定域名记录 + 免责提示；App 启动预取一次锚定页保活 Cookie；文档写明"两周未用需重扫一次属正常" |
| P3 | 隧道快速地址每次重启变化，配对失效 | 会话锚定 relay 固定域名（S4）；快速地址仅首次入口 |
| P4 | relay 中继未生效（网络/注册失败）→ 只有快速地址可用 | 落地后检测：无 relay 则明示"当前为临时地址，重启电脑需重扫"；不静默假装稳定 |
| P5 | Service Worker 不注册（部分国产 WebView 内核差异） | ServiceWorkerController 显式初始化；失败不阻塞主流程（SW 只影响书签直达，App 内本来常驻）；文档记录已知机型 |
| P6 | 相机权限被拒 | 引导页+跳系统设置；扫码入口保留，权限补授权后即用 |
| P7 | 返回键直接退出 App（WebView 默认行为） | 返回键=goBack，历史空才退出（S3） |
| P8 | 扫码时令牌已过期（面板码有时效） | 403/超时识别 → "请刷新二维码重扫"；扫码页放"刷新说明"链接 |
| P9 | 审批/通知在 WebView 模式无系统通知 | 一期如实声明限制；二期不做（JS 桥接转发工程量大，单独立项） |
| P10 | 用户误以为扫码模式替代桥接模式 | UI 明示两种模式适用场景；桥接入口原样保留 |
| P11 | Android 12–15 各版本相机/WebView 行为差异 | minSdk 26 覆盖面已广；扫码库自带适配；真机验收覆盖用户机型 |
| P12 | GitHub 误推敏感文件 | 策展副本模式 + 推送前 `git grep` 脱敏扫描清单化核销；仓库 private 起步 |
| P13 | 仓库超限（APK/工具链） | APK 走 Releases；AndroidSdk/jdk/gradle 等 3.8GB 构建缓存不进库（.gitignore） |
| P14 | push 走代理失败 | git 一次性 `-c http.proxy=http://127.0.0.1:7890`；失败重试不换源 |
| P15 | 中文路径 + Git/Gradle 坑复发 | 导出副本目录用**纯 ASCII 路径**（D:\dsh-mobile-console-github），规避全部已知 GBK/路径问题 |
| P16 | 插件升级改协议（配对 URL 格式变化） | 白名单按域名级（非全 URL 匹配）；升级破坏时只需更新解析函数，单点维护 |
