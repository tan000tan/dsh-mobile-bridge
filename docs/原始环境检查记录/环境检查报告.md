## 4. 对本项目的关键结论

1. 本机 DSH 0.1.7-rc.2 的 web profile 默认监听 127.0.0.1:3080，官方 CLI 明确拒绝 0.0.0.0 绑定（官方文档原文：`--host 0.0.0.0 is intentionally not supported yet for safety: it would expose remote code execution`）→ 手机跨机访问必须经电脑端桥接（反向代理），且桥接不修改 DSH 任何文件/配置即合法。
2. 认证链：`dsh web` 启动时打印一次性 launch token → `GET /?token=<t>` 换 `dsh-auth-*` 签名 Cookie（HttpOnly/SameSite=Strict，默认30天）→ 后续 /api 与 WS 携带 Cookie。token 不可用于 /api 路径与 Authorization 头（本机安装包 lib 中已验证 launchToken/cookieMaxAgeDays 字符串存在）。
3. DSH 每次重启生成新 launch token → 凭据生命周期设计必须支持"重启后换 token"，不得持久化过期凭据（借鉴 DSH-Remote 的教训）。
4. 无 CHANGELOG/SECURITY.md；版本差异记录在官方仓库 docs/upgrade-guide/；0.2.1-alpha.2 才新增 `/connect` API 接入端点，0.1.7-rc.2 无（外部客户端走浏览器式 token→cookie 路径）。
