# 升级与回滚文档（阶段 D）

适用范围：本项目（DSH 手机控制台 + dsh-bridge）。约束回顾：DSH 本体升级**完全手动**（需求 #41）；系统/网络/DSH 变更须批准（#17）。

## 一、版本记录

| 组件 | 当前版本 | 标识 |
|---|---|---|
| 手机控制台 APK | 0.18.0-适配版（fork 基座 93a7910 + 本次适配） | SHA-256 见《最终验收报告》 |
| dsh-bridge | v1.1.0（桥接配置/代码内 VERSION） | 桥接启动横幅打印 |

## 二、升级：手机控制台 APK

1. 在本机重新构建（无联接路径）：`gradle -p 手机端源码\复用DSH_Mobile客户端\dsh-mobile :app:assembleDebug`（详见可复现构建报告）。
2. 计算并核对新 APK 的 SHA-256（`certutil -hashfile <apk> SHA256`）。
3. 覆盖安装（adb install -r 或手机上直接安装同签名包）；**数据不迁移**——主机配置以 Keystore 加密存于应用私有目录，覆盖安装保留；卸载重装则需重新配对（重新粘贴主机地址）。
4. 回滚：重装旧版本 APK 文件（交付目录中保留哈希记录的上一版）。若新版本升级了 DataStore 格式导致旧版不可读，回滚=清除应用数据后重新配对（配置仅凭据与设置，可重建）。

## 三、升级：dsh-bridge

1. 替换 `电脑端桥接服务源码\dsh-bridge\bridge.js`（新版本），保持 `桥接配置.json` 与 `devices.json` 不动——v1.1.0 起设备台账向后兼容旧单令牌配置（自动迁移为 default 设备）；**v1.1.1 起设备台账跨进程热重载**：CLI 的 revoke/rotate/add 对运行中的桥接即刻生效（按文件 mtime 感知），无需重启。
2. 重启桥接（托盘菜单或重跑启动脚本）；核验启动横幅版本与指纹。
3. 回滚：用旧版 bridge.js 覆盖回并重启；v1.1.1 之前的行为差异——旧版不感知运行中的台账变更（撤销需重启才生效），devices.json 若是新版格式，旧版会忽略它继续用配置内 token（设备级撤销能力随之丢失——如实记录的代价）。

## 四、升级：DSH 版本变化（0.1.7-rc.2 → 0.2.x 及以后）

1. **不自动适配**（#41）：升级 DSH 前先在本项目记录目标版本号。
2. 已知兼容矩阵（兼容性报告）：客户端的接入路径两版通用；`/connect` 为 0.2.x 新增（客户端不依赖）；0.2.1-alpha.1 起 `webRuntime`→`webStartup` 等为服务器内部变化。
3. 升级后验证清单（按《真实环境验证准备与授权清单》第一节执行一遍）：连接→会话→事件→审批→断线恢复；任何一步失败→**暂停不兼容功能**（客户端对 404 能力自动隐藏，属预期），在台账登记并等待决定。
4. 回滚：`npm i -g @deepseek-ai/dsh@0.1.7-rc.2`（由你执行；本项目不动 DSH）。

## 五、迁移说明

- 旧版（单令牌）桥接 → v1.1.0：自动迁移，原令牌成为 `default` 设备，明文不再落盘；原手机连接**无需改动**即继续工作。
- 明文 hosts 配置 → Keystore 加密：首次启动新 APK 后首次写配置时自动加密；回退场景（Keystore 失败）按明文落盘并在文档声明。
- 搜索/主题切换入口移除（基线 #68/#87）：仅 UI，无数据迁移。
