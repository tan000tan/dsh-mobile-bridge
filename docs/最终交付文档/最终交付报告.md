## 1. 最终采用的架构

```
Android 手机（DSH Mobile 客户端，复用+适配）
   │  http://<电脑IP>:3090/<桥接令牌>/api/...  + WS /api/remote.mux
   ▼
dsh-bridge（Node.js 零依赖反向代理，默认仅绑定 127.0.0.1，本次新开发）
   │  仅出站转发到 127.0.0.1:3080（Host 头重写，凭据 fail-closed）
   ▼
DSH web profile（你手动 `dsh web` 启动，本项目零修改、不自动启停）
```

要点：手机端以 URL 路径前缀携带桥接令牌（应用原生 basePath 支持）；DSH 自身 launch token→cookie 认证链路原样保留；审批经 `$events` waterfall→`$events/result` 回到 DSH 进程内（与桌面浏览器同一机制）；"电脑离线 vs DSH 未启动"由桥接 `/bridge/status` + HTTP 502 语义区分；无公网服务器、无账号体系、无中继。

## 13. 如何构建、安装和使用（授权范围内）

**首次使用（电脑端）**
1. 你手动启动 DSH：`dsh web`（保持默认 127.0.0.1:3080；重启 DSH 后需换新 launch token）。
2. 启动桥接：`电脑端桥接服务源码\dsh-bridge\启动桥接服务.bat`（首次运行自动生成 桥接配置.json 与 64 位令牌，横幅会打印手机端应填地址）。
3. 局域网使用：把 桥接配置.json 的 listenHost 改为电脑内网 IP（启动横幅会警告），建议全程 Tailscale/WireGuard 承载。

**手机端**
4. 安装 构建产物与安装包\DSH手机控制台_debug_0.18.0-适配版.apk。
5. 连接页选 Local network，主机地址填横幅打印的完整地址（含令牌路径），端口 3090，点 Connect。
6. DSH 重启后：电脑端横幅会有新 launch token，手机端重新粘贴连接即可。

**重新构建 APK（推荐：完全无联接，全部在项目目录内——阶段二已实测）**
```
cd D:\Agent工作区\ZCode工作区\DSH手机远程控制台
set JAVA_HOME=D:\Agent工作区\ZCode工作区\DSH手机远程控制台\临时文件与构建缓存\jdk17\jdk-17.0.20.1+1
临时文件与构建缓存\gradle-8.11.1\bin\gradle -p 手机端源码\复用DSH_Mobile客户端\dsh-mobile :app:assembleDebug
```
（依赖 fork 内 `gradle.properties` 的官方开关 `android.overridePathCheck=true` 与指向项目内 SDK 的 `local.properties`，均为阶段二配置并实测。）
如需以 Gradle 原生方式运行单元测试，须先 `bash 电脑端桥接服务源码\建立构建联接.sh` 重建 ASCII 联接（JDK17 测试工作进程的 @argfile 编码限制，详见 可复现构建与路径审计报告.md），或使用已实测的无联接直跑方案（JDK25 JUnitCore，工具在 自动化测试与测试结果\）。
