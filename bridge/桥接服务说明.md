# dsh-bridge 桥接服务说明

零第三方依赖的 Node.js 反向代理（v1.1.0）。作用：把手机端对 DSH web profile 的访问反向代理到仅回环监听的 DSH（127.0.0.1:3080），使手机跨机访问**无需修改 DSH 任何文件或配置**（0.1.7-rc.2 官方拒绝 0.0.0.0 绑定）。

## 运行形态（需求 #12/#28）

- **托盘程序（默认推荐）**：双击 `启动托盘.bat`——托盘菜单：启动/停止桥接、状态、退出；不安装服务、不写注册表、不开机自启。
- **命令行前台**：`node bridge.js`。
- **Windows 后台服务**：仅提供思路（`sc create` 需管理员），安装须你批准并亲自执行——本项目不代为安装。

## 设备管理（需求 #25/#26/#38/#59，本机 CLI 执行）

```
node bridge.js devices list              # 设备列表（id/名称/撤销状态/最近活跃）
node bridge.js devices add <名称>        # 注册设备，明文令牌只打印一次
node bridge.js devices revoke <设备id>   # 撤销：即刻失效（活跃连接下一次请求被拒）
node bridge.js devices rotate <设备id>   # 轮换：旧令牌即刻失效
```

- 台账 `devices.json` **只存令牌哈希**；旧版单令牌配置自动迁移为 default 设备（原令牌平滑有效）。
- 撤销/轮换即刻生效——失窃设备的处置路径（基线 #25）。

## 滥用防护与审计（需求 #24/#33/#43）

- 认证失败限速：同一来源 60 秒内失败 ≥10 次 → 临时封禁 5 分钟（返回 429），并写审计告警。
- 审计日志：`审计日志\audit-日期.jsonl`（JSONL；等级 info/保留 30 天可在配置 `audit` 节调整）；**绝不记录令牌、Cookie、URL 查询串、请求体**。

## TLS（需求 #29，可选，配置后禁降级）

1. 运行 `建立TLS证书.ps1`（在本机证书库创建自签证书并导出 PFX/CER 到本目录，运行属你批准事项）。
2. 按脚本打印的说明在 `桥接配置.json` 增加 `"tls": { "pfxPath": "...", "passphrase": "..." }`。
3. 重启桥接——**此后仅 HTTPS 监听**（明文 HTTP 不再可用）；横幅打印证书 SHA-256 指纹供手机端核对。
4. 手机端安装 `.cer` 为用户 CA 后，主机地址改用 `https://`。

## 配置文件字段（桥接配置.json）

| 字段 | 默认 | 说明 |
|---|---|---|
| listenHost | 127.0.0.1 | **默认仅回环**。局域网访问改为电脑内网 IP（启动横幅警告） |
| listenPort | 3090 | 桥接监听端口 |
| dshHost / dshPort | 127.0.0.1 / 3080 | DSH web profile 地址（仅出站） |
| tls | null | `{pfxPath, passphrase?}`——配置后仅 HTTPS（禁降级） |
| audit | {level:"info", retentionDays:30} | 审计等级与保留期 |
| auditDir | 配置同目录\审计日志 | 审计文件目录 |
| token | （迁移用） | 旧版单令牌；存在且无 devices.json 时自动迁移 |

## 安全设计

1. **三层凭据**：桥接设备令牌（可撤销/轮换）+ DSH launch token→cookie（每次 DSH 重启轮换）+ DSH 侧审批（执行边界）。
2. **常量时间比较**；**fail-closed**（无有效设备/空令牌拒绝启动，401/429）。
3. **Host 重写**仅为通过 DSH 栅栏；不伪造 Origin、不透传桥接令牌。
4. **日志/审计脱敏**（有测试断言）；**DSH 停止时如实 502**，不伪造响应。
5. **状态区分**：`GET /<令牌>/bridge/status` → `{bridge, dsh:"running"|"not_running", tls, serverTime}`。

## 生命周期

托盘/前台手动启动，Ctrl+C 或托盘退出；崩溃不自动重启（不掩盖故障）；无守护、无自启、无服务安装。DSH 永远由你手动启动。
